## Функциональные требования
1. Регистрация и вход
 - Регистрация. Создает пользователя по никнейму и паролю. Сразу логинит его, возвращая токен и созданного пользователя.
 - Вход. Логин по никнейму и паролю. Возвращает токен и пользователя.
2. Пользователи
 - Список всех пользователей, кроме залогиненого. С отметкой нахождения в сети.
 - Вшитая сортировка по онлайн статусу, затем по никнейму.
3. Сообщения
 - Хранимая история личных сообщений с указанным пользователем
 - Статусы сообщений "отправлено", "доставлено", "прочитано"
 - Отправка и прием сообщений через WebSocket
 - Изначальный статус отправленного сообщения - "отправлено"
 - Если получатель онлайн, сервер сразу отправлет ему новое сообщение, а для отправителя выставляется статус "доставлено"
 - Если получатель оффлайн, то он должен получить все отправленные ему сообщения при следующем подключении к серверу с соответствующей сменой статуса сообщений.
 - Прочтение: клиент отправляет серверу сообщение о прочтении, сообщение меняет статус на "прочитано". Прочтианным считается сообщение когда пользователь открыл чат с этим сообщением.
4. WebSocket
 - Эндпоинт с токеном
 - Формат сообщений: JSON. Сам определи минимально необходимый, самый базовый набор полей в json.
 - Сессии храни в потокобезопасной структуре, при закрытии соединения обязательно удаляй соответствующую сессию, уведомляй о статусе пользователя (онлайн - сессия активна, оффлайн - нет активной сессии)
 - используй try/catch, обрабатывай исключения, отправка должна быть потокобезопасной
5. Таблицы БД
 - Пользователи (минимум полей - id, никнейм, хеш пароля)
 - Сессии
 - Сообщения (минимум - id, статус, отправитель и получатель, текст сообщения, время)
 - Используй индексы для таблицы сообщений, типичные для чат приложения, для быстрой загрузки истории сообщений между двумя пользователями в правильном порядке.
6. Клиентская часть
 - Простое web SPA приложение. Может отдаваться сервером как статика - как сочтешь нужным. Можно написать на голом JavaScript + HTML + CSS
 - Форма регистрации и входа. Токен в localStorage
 - Слева узкое окно со списком пользователей с индикаторами онлайн/оффлайн и поиском по никнейму
 - Справа окно чата: история переписки с временем отправки и статусом сообщений, поле ввода с кнопкой отправки
 - Для статусов используй иконки галочек: одна - отправлено, две - доставлено, две другим цветом - прочитано
 - При регистрации происходит автоматический логин под нового пользователя
 - WebSocket подключается автоматически после логина, при разрыве соединения - пытаться переподключиться
 - Если у пользователя прервалось WebSocket соединение - отображай статус оффлайн
7. Dokcer
 - Multistage: первый - сборка проекта, второй - запуск.
 - В docker-compose.yml включен сервис postgres с образом PosgreSQL (используй volume для сохранения данных между сборками) и сервис simple-chat-app.

 - Описание архитектуры проекта
 - Требования (JDK нужной версии, Docker и тд)

 - Команды для сборки

## Стилистические требования
 - Используй Lombok для улучшения читаемости и уменьшения бойлерплейта
 - Используй conventions принятые для Java 25 версии
 - Неизменяемые коллекции создавай через List.of(), Set.of() и тому подобные
 - Для многострочного текста используй текстовые блоки """
 - Используй enhanced switch и паттерн-матчинг вместо громоздких if else конструкций
 - Бины-сервисы делай через аннотацию @Service
 - Используй DependencyInjection через конструктор с аннотацией @RequiredArgsConstructor, без @Autowired полей
 - Имена методов должны быть глаголами, а классов - существительными, без I перед названиями интерфейсов


## Критерии приемки
 - Проект собирается одной командой без ошибок (./gradlew build)
 - Запускается и обслуживает запросы
 - Два и более пользователей могут зарегистрироваться, войти одновременно, найти друг друга в списке и отправить личные сообщения
 - Сообщения сохраняются в базе PostgreSQL и доступны после перезапуска
 - Смена статусов пользователей и сообщений работают в реальном времени по WebSocket
 - Оффлайн-пользователь получает недоставленные сообщения при следующем подключении
 - Веб-клиент работает без отдельных сборок
 - Docker-сборка запускается и обслуживает приложение
